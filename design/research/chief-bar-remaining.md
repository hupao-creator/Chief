# Chief Bar transition boundaries

The production change is confined to the two resident eye layers. An unread
Chief reply, marking it read, or an intervention can change the compact face
while the Bar, controls and decorations stand still. The original controller
supplies the 420 ms Hermite trajectory. Each shape layer receives position,
tilt and rounded-path tracks on a common media clock. A reversal retains the
incoming velocity and its turning point. Overlapping blinks, a different
velocity for each component, resizing, and coordinated role changes use the
display link. Hiding the face withdraws the submitted track at its logical
pose. [Character and blink ownership](../../app/macos/Sources/Host/MokuScene/README.md#dock-and-composer)

The comparison starts from `9b61af09226e12e0c414273cf077154815e01e0a`.
The independent-seat and expansion reports and their original evidence are in
Git object `44fec23d4c59200821ae5be23fb395f8294c13cd`, under
`design/research/chief-bar-independent-seats.md` and
`design/research/chief-bar-expansion.md`. They document the failed rehosted
material and editor, retained route host, document carriers and projected
identity planes. The separate Stop integration owns Stop. [Replay instructions](../../demos/moku-panel-transition/remaining/README.md)

## Material, reading and identity

The bare-mask trial leaves the content, native material and responder in
their original hierarchy. It measures full, half and zero alpha, with two
independent ordinary-opacity visits at the same device coordinates. A red
control verifies alpha transfer. Per-channel residuals are measured outside
the pointwise range of the two originals. A second measurement selects the
pixels visibly changed by the tested element in both originals.

| Surface | Finding and condition for a production change |
| --- | --- |
| Capsule glass | Masking the original clear glass changes the full-strength rim as well as the half-strength body. A usable technique must retain the native backdrop sample, optical edge and the clear-to-regular exchange during resizing. |
| Composer | Masking the mounted final-width editor alters the controls and text at held opacity. Keeping the text view in place solves its ownership only. The original geometry-coupled reveal and focus handoff still govern first-key admission, marked text and narrow reflow. |
| Note | The mask changes pixels inside the original page's ink. The Note also owns exposure, the 100 ms outgoing ink, shell travel, the 120 ms incoming ink and completion before linked reading. |
| Talk | The live scroll view can fade independently under a bare mask, and fixed alpha levels can match the selectable text. Simply replacing the outer opacity releases the Note sequence early. A SwiftUI animation participant restores completion ordering. With a transaction-aware additive opacity on the mask, the actual open, close and interrupted return still differ from both original lanes. The scroll offset survives. Ordinary Talk insertion/removal has its own 220 ms transition. Dispatch uses a different view. |
| Settings | The actual mounted Settings page differs inside its ink at held mask levels. The original modal shell, page placement, close/reopen, form controls and draft ownership remain necessary for a whole-page migration. |
| Harness identity | The built-in 3D rotation on the original SwiftUI Codex artwork differs at held angles and fails to supply a distinct sequence of independently displayed silhouettes during a main-thread hold. The visible projection and its guard for the invisible edge-on face keep their existing implementation. |

The capture uses complete ScreenCaptureKit frames belonging to the helper.
Free-running hold analysis requires both display and delivery inside the
recorded main-thread interval. Held-phase comparisons use sRGB window pixels
at native resolution. These workloads establish the listed properties on the
tested machine. They do not measure physical scan-out or a workspace FPS
budget. [Reproducible visits](../../demos/moku-panel-transition/remaining/README.md)

## Recorded run

The 13 visits ran on production source `56d2e65d4163ca75db3422b5a15d592c242c3575`
with an empty production diff. The helper linked that commit's Debug modules
on arm64 macOS 26.5.1 (25F80), SDK 26.5, at 2× backing scale. All 13
completed in separate processes with the same foreground PID before and
after each visit. A completed diagnostic means its observation was collected.
The optical decisions below use the recorded pixels.

The same revision built the Release Chief with the resolved dependencies and
Swift warnings as errors in 200.7 s wall time (198.02 s reported by SwiftPM).
The binary SHA-256 is `9a3407944ac7fad27cc1bd2ec1022c0a7bc08e9fc00bafe2e1fa39183750c5ee`.
The commit hook passed architecture checks, formatting and Go vet. This
detached handoff has no hosted CI result or combined-branch validation.
