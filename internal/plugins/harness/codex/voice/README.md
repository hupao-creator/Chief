# Codex global voice relay

The macOS host holds one [GlobalVoiceSession](../../../../../app/macos/Sources/Voice/README.md) per workspace. The authenticated runtime grants one call per profile. Moku resolves the current Chief, pins its owner and supplies the relay with an SDP offer, an answer callback, destination admission and a stream of committed Talk replies. The selected Chief Harness owns work and tools. Codex supplies the voice connection even when another Harness runs Chief.

## Native session

Each call launches its own app-server through [Codex executable discovery and isolated native authentication](../README.md). The relay needs a ChatGPT account on the native OpenAI provider. It queries the V3 voice inventory and the account's model catalog. It prefers the advertised `gpt-6-luna` backing model and otherwise selects the explicitly advertised default. Thread admission confirms the exact model, native provider, read-only sandbox and disabled approvals. Tool surfaces are disabled. The relay uses a temporary workspace and private native history home, both released when the call ends.

The start request selects realtime V3, WebRTC, audio output and client-managed responses. Its product call ID and native realtime session ID have distinct lifetimes and meanings. Readiness requires matching session and version plus the SDP answer for this native thread. Account, unsupported-method, empty inventory, negotiation, model and process failures reach the caller. The media handshake checks availability for the current call.

## Handoff and speech

The sole input source is a committed V3 `thread/realtime/item/completed` whose timeline item has `type: transcriptSegment`, `role: user` and the confirmed realtime session ID. The native segment ID is the handoff ID to Chief. This ID travels unchanged into the destination receipt. Codex's discretionary background delegation uses a separate identifier and can be absent for a fully transcribed request. It has no execution authority in Chief.

The relay orders user segments by their first native event. If a later transcription completes first, it waits for earlier segments to complete or time out. An empty completion also releases its place in that order. The relay retains an identity digest until stop so repeated delivery cannot repeat work. Distinct segment IDs carrying identical words are independent inputs. Conflicting reuse, malformed completed input, queue overflow or uncertain admission end the call. Partial transcripts, assistant speech and backing-turn notifications cannot submit work.

The [destination admission](../../../../services/moku/README.md#global-voice) records the product call ID, native handoff ID and actual execution ID. The sideband accepts speech only for that live binding. Each successful public Talk triggers one append of its original text. The relay waits for open native assistant speech segments to finish before appending, then waits for the pending Talk’s words in newly completed assistant transcripts before the next append. A Talk can span multiple segments. The comparison tolerates changes in case, whitespace and punctuation. V3 provides no append ID in those segments, so identical spoken words have the same confirmation. The RPC can accept a fast Talk while the voice frontend is speaking and omit it from playback. A voice confirmation timeout ends the call and leaves the public Talk in the conversation. The start of a newer user segment immediately retires pending speech, even while transcription is in progress. A completed blank segment creates no input. An interrupted append is never retried because the peer may already have accepted it. Audio already accepted remotely may finish playing. The native frontend can briefly acknowledge hearing speech. Only the destination's committed Talk is published in the Chief conversation.

After 30 seconds without transcription progress on an unfinished user segment, the relay skips that segment and releases any completed inputs next in order. The call remains open. The relay remembers the skipped segment ID until hangup and ignores late events for it. The call bounds unfinished and queued admissions together to 32, bounds queued Talk replies to 32 and retains up to 1,024 distinct handoffs. Peer loss, a closed lease and runtime shutdown retire the call, release its process and revoke queued work. A user may explicitly start a fresh call. Already admitted business execution retains the ordinary Chief lifetime.
